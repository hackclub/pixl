Git and GitHub

Almost every trial you ship should end up on GitHub somewhere, both because reviewers want to see your code and because it's just how you avoid losing your work.

Getting Git installed

If you're on Mac, Git is usually already there, open your terminal and type git --version to check. On Windows, grab Git for Windows from git-scm.com and install it with the default options. On Linux it's normally sudo apt install git or whatever your package manager uses.

Setting up your identity

Before your first commit, tell Git who you are:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Use the same email as your GitHub account so your commits actually get linked to your profile.

Starting a new project

Inside your project folder:

git init
git add .
git commit -m "first commit"

Then head to GitHub, make a new repo, and it'll give you a couple lines to run that connect your local folder to it, something like:

git remote add origin https://github.com/yourusername/yourproject.git
git branch -M main
git push -u origin main

The everyday loop

Once it's set up, the loop you'll use constantly is:

git add .
git commit -m "what you changed"
git push

Commit often, and write messages that actually describe what changed, "fixed navbar overflow on mobile" is a lot more useful later than "update."

A .gitignore is worth setting up early

You don't want to accidentally commit API keys, node_modules, or build files. Create a .gitignore file in your project root and add lines like:

node_modules/
.env
dist/

GitHub has starter .gitignore templates for pretty much every language if you search "gitignore [your language] github."

Why this matters for trials

A lot of submissions ask for a repo link, and reviewers do actually look at your commit history sometimes, it's one of the ways they can tell a project was built over real hours instead of dumped in all at once right before a deadline.
